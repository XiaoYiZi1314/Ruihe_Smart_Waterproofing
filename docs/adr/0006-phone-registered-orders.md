# ADR 0006: 电话登记使用正式工单

## 状态
已接受

## 背景
部分客户打电话预约，不愿意扫码使用小程序。客服需要把沟通结果记进系统，后续才能指派师傅、导出和对账。若另做“来电台账”，工单管理会裂成两套。

## 决策
1. **电话登记创建正式工单**，状态为待确认，之后指派、施工、更正与小程序预约相同。
2. **用来源区分**：`miniapp`（小程序预约）或 `phone`（电话登记）。不另建工单类型。
3. **按手机号复用或创建客户账号**，同一号码的多次来电归到同一客户，便于复盘。
4. **地址写在工单上**，并为该客户补一条地址簿记录，以保持现有外键。
5. **不做 Excel 批量导入**。来电是一单一登；批量文件无法可靠对应服务项目和预约时段。

## 理由
- 客服要的是“进工单管理”，不是独立笔记。
- 电话客户通常不会在小程序里点验收；现有 3 天自动完成和状态更正中的强制完成已经覆盖卡住的单。
- 占位客户账号比把 `user_id` 改成可空更安全：通知、评价、历史查询都还能挂在人上。
- 按手机号合并，避免同一来电客户每次登记都变成新人。

## 后果
- 电话登记的工单会出现在师傅端；完工后若客户没有小程序，需依赖自动完成或管理员强制完成。
- 若该手机号后来绑定了微信客户，历史电话单会显示在其“我的工单”里。这是有意为之。
