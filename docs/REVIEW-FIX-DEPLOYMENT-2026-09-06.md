## 微信平台与发布边界

- 仅发布 `miniapp/`。`miniapp-worker/` 是历史备份，不是第二个发布包。
- 小程序源码修改尚须在微信开发者工具中上传体验版、真机验收并提交发布，不能通过部署 Node 后端替代。
- 服务器当前没有配置订阅模板。站内消息可以保留通知，但不能据此声称微信消息已送达。
- 指派通知区分 `WECHAT_TEMPLATE_WORKER_ASSIGNED` 和 `WECHAT_TEMPLATE_CUSTOMER_ASSIGNED`，两种接收人的字段不同，不能简单填同一模板。
- 其他模板环境变量见 `backend/.env.example`，实际模板字段需与 `backend/src/utils/notification.js` 对齐。微信订阅受用户授权次数限制，不能保证持续后台推送。
- 需真机验证真实微信绑定、授权订阅、图片预览、视频选择/播放、扫码进入后的角色分流及表单键盘布局。当前 MP4 回归仅验证上传协议和存储链路，不是播放兼容性测试。
- 当前限制：图片每张 5 MB、视频 128 MB、每用户附件总额度 512 MB。Nginx 已放宽到 130 MB 以容纳 multipart 开销。
- 签名 URL 是短期可转发的访问凭证；住宅图片请勿主动分享。管理员宣传图和已发布评价的视频按展示用途公开。
- 验证环境：Node 20.20.2、MySQL 8.0.46。后台构建工具链使用 Vite 7，开发环境需 Node 20.19+ 或相应受支持的新版本。
- 当前限流为单进程内存存储；如以后扩展多个 PM2 实例/多服务器，应迁移到共享限流存储。
- 建议轮换曾通过聊天或历史文档传递的登录凭据；本轮不在报告中重复任何密码。
