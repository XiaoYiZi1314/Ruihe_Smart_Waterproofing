# 工单状态同步修复与发布记录

日期：2026-09-21（Asia/Shanghai）
发布批次：`20260921-142504-order-sync`

## 问题定位

用户反馈师傅已接单并开始施工，管理员列表仍显示待接单。

只读查询生产工单 `RH2026092100001`（id=7）：最初检查时数据库状态已为 `in_progress`，接单时间为 14:16:24、开工时间为 14:16:51，操作日志存在 accept/start。说明业务流转已保存，并非师傅操作丢失。

根因：`orderWorkflow.transition` 完成数据库事务后没有调用已有的 `Realtime.notifyOrderChange`；管理端虽然监听 `order:changed` 并刷新列表，却收不到这一路事件。同时，管理端固定将 `confirmed` 显示成“待接单”，未区分 `confirmed_at` 已有值的已接单工单；已打开的详情抽屉也没有随事件刷新。

## 修复

### 后端

文件：`backend/src/utils/orderWorkflow.js`

- 在统一状态流转入口、事务 commit 成功后发布 `order:changed`，含工单 ID、提交后的状态和动作类型。
- 覆盖接单、开工、拒单、完工及其他走统一工作流的状态流转。
- 返回提交后的状态，不再返回变更前状态。
- 提交失败和校验失败不发送事件。
- 推送异常被独立处理，不会把已经提交的业务操作报告成失败或尝试回滚。

### 管理端

文件：`admin/src/views/Orders.vue`

- `confirmed` 且未接单：待接单。
- `confirmed` 且有接单时间：已接单，待开工。
- `in_progress`：施工中；其他状态保留原映射。
- 工单事件同时刷新当前筛选/分页列表及正在查看的详情。
- 页面可见时每 15 秒静默刷新；窗口重新获得焦点或页面恢复可见时立即刷新。
- 新增请求序号与卸载保护，旧响应不能覆盖最新列表或其他工单详情，关闭的抽屉不会被异步响应重新打开。
- 页面卸载时清理定时器及监听器。

未修改数据库表结构、真实工单状态、师傅账号、价格或其他业务数据。
