# ADR 0001: 单管理员单师傅工单流程

## 状态
已接受

## 背景
防水预约管理系统需要设计工单的指派和协作模式。初始讨论中考虑过多师傅协作的可能性，但经过需求讨论后决定简化流程。

## 决策
1. **一个工单只能指派给一个师傅**，取消多师傅协作功能
2. **只有一个管理员账号**，不做权限分级
3. **师傅不能抢单或自行接单**，完全由管理员指派

## 理由

### 为什么取消多师傅协作？
- 防水施工业务中，大部分工单是单人即可完成的小型工程
- 多师傅协作会引入复杂的状态同步问题：
  - 谁来控制工单状态？
  - 价格由谁填写？多人如何分配？
  - 一人拒单如何处理？
- 真正需要团队的大型工程，可以通过线下协调，系统中仍指派一个"主师傅"
- 简化状态机和UI设计

### 为什么单一管理员？
- 目标客户是个体工商户或小型防水公司
- 通常由老板或办公室人员统一调度
- 权限分级会增加系统复杂度和培训成本
- 如未来业务扩大需要多管理员，可通过新版本迭代

### 为什么不支持抢单？
- 防水服务需要考虑地域、师傅技能匹配
- 管理员更了解师傅的能力和当前工作负荷
- 抢单可能导致客户体验不一致（就近原则被打破）
- 师傅可通过拒单机制反馈无法接单的情况

## 后果

### 正面影响
- 工单状态流转简单清晰
- 开发和测试成本降低
- 用户学习成本低
- 管理员有完全的调度控制权

### 负面影响
- 管理员工作量相对较大（需手动指派）
- 无法支持师傅自主选择工单
- 大型工程需要线下协调，系统中无法体现多人协作

### 缓解措施
- 提供师傅在线状态展示，帮助管理员快速识别可用师傅
- 统计师傅拒单率，帮助管理员优化指派决策
- 工单可被师傅拒绝，拒单后自动回到待确认状态，管理员可重新指派
