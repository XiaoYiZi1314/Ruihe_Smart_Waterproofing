# ADR 0004: 不配置在线支付功能

## 状态
已接受

## 背景
防水服务通常涉及金额支付，需要决定是否在系统中集成在线支付功能（如微信支付）。

## 决策
整个系统不配置在线支付功能，所有支付线下完成（现金、转账、扫码等）。

## 理由

### 为什么不做在线支付？
1. **业务特性**：
   - 防水服务的最终价格只能现场评估后确定
   - 价格可能需要协商调整
   - 客户通常希望验收后再付款
   - 线下支付方式已被广泛接受（现金、微信转账、扫码）

2. **资质和成本**：
   - 微信支付需要企业资质和认证费用
   - 需要对接支付接口、处理退款、对账等复杂流程
   - 增加开发和维护成本

3. **风险控制**：
   - 在线支付涉及资金安全，需要更严格的测试和监控
   - 纠纷处理复杂（退款、部分退款、服务质量争议）
   - 个体工商户可能没有完善的财务流程来处理线上资金

4. **用户习惯**：
   - 目标客户群（个体工商户、小型公司）习惯线下收款
   - 客户更倾向于验收满意后当面支付
   - 线下支付灵活性更高（可议价、可分期、可调整）

## 后果

### 正面影响
- 大幅降低开发和维护成本
- 避免支付相关的法律和安全风险
- 简化工单流程，专注于核心调度功能
- 支付方式更灵活，适应实际业务需求

### 负面影响
- 无法在系统内追踪实际支付状态
- 无法生成自动化的财务报表
- 客户无法在线支付定金或全款
- 可能存在客户拖欠款项的风险

### 缓解措施
- 工单中记录"最终价格"，管理员可导出用于财务对账
- 如未来业务扩大确需在线支付，可作为独立功能模块在后续版本中迭代
- 管理员可在"备注"或"价格"字段中标注支付状态（需手动维护）

## 未来考虑
如业务发展到一定规模，可考虑在V2版本中增加：
- 在线支付定金功能（锁定订单）
- 支付状态追踪（已付/未付）
- 财务报表导出

但当前阶段（V1），不做在线支付是最合理的选择。
