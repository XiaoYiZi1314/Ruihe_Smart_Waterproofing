# ADR 0003: 异常状态自动化检测

## 状态
已接受

## 背景
工单指派给师傅后，如果师傅长时间未响应，会影响客户体验和工单流转效率。需要一个机制来识别和处理这类情况。

## 决策
1. **系统自动检测**：工单指派后24小时（自然日）师傅未响应，自动标记为"异常"状态
2. **响应定义**：师傅必须点击"开始施工"才算响应，仅查看工单不算
3. **自动解除**：师傅后续响应后，异常状态自动解除
4. **无特殊流程**：异常工单可正常流转，无需管理员手动处理
5. **数据展示**：工作台看板单独统计"异常工单数"

## 理由

### 为什么设定24小时阈值？
- 防水服务通常不是紧急服务，24小时是合理的响应窗口
- 过短（如6小时）会产生过多误报（师傅下班、休息）
- 过长（如48小时）会让客户等待过久，影响体验

### 为什么只有"开始施工"才算响应？
- 拒单也是一种明确响应，会改变工单状态（回到待确认）
- 仅查看工单不能代表师傅做出决策
- 明确的行为（开始施工/拒单）才能推动工单流转

### 为什么自动解除而非手动处理？
- 异常状态的目的是"提醒"，不是"阻塞"
- 师傅响应后问题已自然解决，无需管理员介入
- 减少管理员操作负担

### 为什么不设计特殊处理流程？
- 管理员已经能看到异常工单统计，可主动联系师傅或重新指派
- 系统自动操作（如强制改派）可能引入误判风险
- 保持流程简单，由管理员根据实际情况灵活处理

## 后果

### 正面影响
- 及时发现师傅未响应的问题
- 管理员可通过看板快速识别需要介入的工单
- 自动化处理，减少人工监控成本
- 不阻塞工单正常流转

### 负面影响
- 24小时可能对某些场景仍偏长（客户急需服务）
- 无法强制师傅响应，仍需管理员线下跟进

### 缓解措施
- 工作台突出显示异常工单数量，引导管理员关注
- 提供工单详情中的"重新指派"功能（如师傅持续不响应）
- 客户可通过"催单"功能主动催促
